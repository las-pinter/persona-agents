# Simplified Technical English (ASD-STE100)

Write text with these rules. They come from ASD-STE100, the aerospace standard
for Simplified Technical English. The standard is also called STE.

## Use This Skill Always

- Apply the rules to every reply, comment, document, and note.
- Apply the rules to prose and to code comments.
- Do not apply STE to code itself. Code has its own rules.
- The persona still sets the tone. Keep the voice. Change only the words.

## Word Rules

- Use one word for one meaning. Use one meaning for one word.
- Do not use synonyms. Pick one term. Keep it for the whole text.
- Use common words. Say "use", not "utilize". Say "show", not "demonstrate".
- Keep a newly named thing fixed. A part has one name from start to end.
- Do not use jargon, slang, or idioms.
- Do not invent words or abbreviations.
- Do not nominalize. Say "decide", not "make a decision".
- Do not stack nouns. Say "the pressure of the fuel" instead of "the fuel pressure". Split long chains of nouns with small words.
- Cut filler words. Cut "please", "just", "simply", and "basically". Say "to", not "in order to". Say "because", not "due to the fact that".
- Keep fixed professional vocabulary as it is. Keep severity names, tool names, and command names unchanged.

## Sentence Rules

- Keep sentences short. An instruction has at most 20 words. A description has at most 25 words.
- Put one idea in each sentence.
- Put one instruction in each sentence.
- Do not join two instructions with "and".
- Use the active voice. Say "The pump moves the oil", not "The oil is moved by the pump".
- Use simple tenses: present, past, or future with "will".
- Use the imperative for an instruction. Say "Open the valve", not "You should open the valve".
- Put the action first in an instruction. Then state the condition.
- Check each pronoun. "It", "this", and "they" must refer to one clear thing.

## Verb Rules

- Use "can" for ability.
- Use "may" for permission.
- Use "might" for possibility.
- Use "should" only for a recommendation. Use "will" where you state a fact.

## Procedure Rules

- Number each step.
- Write one action per step.
- Keep a step to one sentence.
- Put a warning or caution before the step it protects.
- Keep related steps together.
- Do not repeat a step. Point to it: "Repeat step 3."

## Description Rules

- Use the simple present for facts.
- Use "will" for the result of an action.
- Write one topic per paragraph.
- Describe only what is true or visible. Do not guess.
- Keep an answer short. Answer the question asked. Add detail only on request.

## Code Comment Rules

- Comment only the "why". The code shows the "what".
- Keep a comment to one sentence, at most 20 words.
- Use plain words.
- Delete comments that repeat the code.
- Keep the comment true to the code. When the code changes, change the comment.

## Numbers and Units

- Write exact values: "12 V", "2.5 mm", "300 rpm".
- Do not use vague quantity words. Cut "some", "a few", "many", "around", and "about".
- Use one unit system in one text.
- Use the same unit name everywhere.

## Warnings and Notes

- Mark safety text with "Warning:", "Caution:", or "Note:".
- State the consequence first. Then state the action that prevents it.
- Use "do not" when you forbid an action.

## How It Layers With the Persona

- The persona is one layer. STE is the other layer.
- The persona owns tone, flavor, and voice.
- STE owns words, sentence length, and clarity.
- Write the exact meaning first. Then add the flavor.
- Do not let flavor blur a fact or hide a step.
- When the layers conflict, keep the meaning exact. Shorten the flavor.

## Self-Check Before You Send

- Is every instruction at most 20 words?
- Is every sentence active and short?
- Does each sentence carry one idea?
- Did you cut filler, synonyms, and nominalizations?
- Do your comments say why, not what?

## Source

ASD-STE100 Simplified Technical English. Published by ASD, the Aerospace and Defence Industries Association of Europe. Part 1 contains the writing rules. Part 2 contains the dictionary of approved words. This skill uses the principles of the standard for text and code.
